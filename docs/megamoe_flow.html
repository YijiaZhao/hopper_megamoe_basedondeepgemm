MegaMoE 完整流程（SM90 / H20，EP8）

整层 MoE 融进 2 个 kernel；跨卡通信用 两处 NVLink scatter 实现，与 GEMM 并行在飞。
Dispatch warp TMA producer warp Decode warp Math warpgroup (WGMMA) Epilogue 跨卡通信 (scatter)

1. 全局：一层 MoE = 2 个 kernel

2. 两处 scatter —— 通信融合的关键

为什么用 scatter 而不是 all-to-all：scatter 是逐 token 的细粒度远程写，不是集合原语， 因此不需要全卡同步，可以由专职 warp 发出并与 WGMMA 重叠 —— 这就是「通信藏进计算」。 用 all-to-all/allreduce 则必须等全体到齐，藏不掉。

3. Kernel 内部三级流水（warp specialization + mbarrier）

三方错拍：TMA 灌 k+1 时 decode 处理 k、WGMMA 算 k−1， 由 full / empty / decoded 三组 mbarrier 串起来。双 math WG 再做 pingpong： 一个跑 WGMMA 时另一个跑 epilogue。
注：这是 ExCP（专职 decode warp）结构。LiquidGEMM（arXiv 2509.01229）实测该结构在 小 batch 反而掉性能，其 ImFP 方案让每个 Compute WG 自解码自 MMA、不回写 SMEM —— 待验证的优化方向。

为什么不需要 reduce kernel：L2 激活的 SF 分组边界（K64）正好等于一个 L1 N-block 的输出宽度， 所以 per-token amax 的规约完全在 block 内（寄存器 + 4-lane shuffle）完成，不跨 CTA。 若改成「全局 per-token」scale，一个 token 的行会横跨所有 N block，就必须再插一个 reduce kernel。
