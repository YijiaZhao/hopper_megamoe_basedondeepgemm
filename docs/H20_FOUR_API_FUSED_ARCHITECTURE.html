2. Split 与 Fused 的真正区别

不是数学公式改变，而是执行生命周期改变

Split backend

Frontend
→
L1 kernel
→
L2 kernel
  • L1 与 L2 是两个独立 persistent kernel。
  • 中间 activation 通过 ring buffer 传递。
  • L1 退出后由 host 启动 L2，存在 launch boundary 和 gap。
  • L1/L2 各自拥有独立 scheduler 生命周期。

Fused backend

Frontend
→
Dispatch + L1 + L2 + Combine
  • 一个 kernel 持续占据 78 个 SM。
  • 使用 full-pool workspace，不复用 Split ring-buffer ABI。
  • L1/L2 依赖由设备端 counter、mask 和 mbarrier 表达。
  • 完成少量 L1 warmup wave 后，可交错领取 L1/L2 task。

3. 单个 CTA 内的角色分工

同一 kernel 内采用 producer / consumer 流水线

Dispatch warps

读取 TopK，统计 expert token，发布远端路由，执行 grid/NVLink barrier，并拉取远端 token。

TMA A loader

Linear1 加载 routed input；Linear2 加载量化中间 activation，并等待对应数据 ready。

TMA B loader

根据动态 task 加载 W1/W2 及量化 metadata。预取的是后续 tile，不是完整模型常驻 L2。

Math + epilogue

执行 WGMMA；L1 epilogue 做 SwiGLU/量化，L2 epilogue 写 Combine buffer，最后完成 TopK 聚合。

7. 收益、代价与边界

收益

  • 消除 L1→L2 的第二次 kernel launch。
  • 设备端交错 L1/L2，减少阶段间空洞。
  • Dispatch、计算、Combine 共享 persistent 生命周期。
  • Workspace cleanup 可与尾部 Combine 重叠。

代价

  • 寄存器、SMEM、barrier 和状态机更复杂。
  • full-pool workspace 通常比 ring buffer 更大。
  • 单 kernel duration 包含跨 rank 等待。
  • 小 M 对 rank arrival skew 特别敏感。

不要误解

  • Frontend 仍是独立 kernel。
  • 中间 activation 仍写 global memory。
  • tile prefetch 不等于完整模型权重驻留 L2。
  • Fused 不保证所有 M 都比 Split 快。
