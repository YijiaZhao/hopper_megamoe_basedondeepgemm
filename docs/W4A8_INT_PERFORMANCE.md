# W4A8-int MegaMoE 18 点性能表（2026-07-14 全新环境认证版）

## 测量口径

- 8×H20-3e，NVLink 全互联，SM 锁频 1830 MHz（每轮 run 前后验证，共 61 次全过），
  测量期间无其他负载（60 轮全部零污染、零重跑）。
- **三列全部同日、同机、全新部署环境复测**（容器/代码树/JIT 缓存从零校验搭建），
  三栈逐 rep 轮转交错，消除机况漂移。
- balanced routing（`DG_BALANCED_ROUTING=1`），三列同口径（FP4 列为其首次
  balanced 口径测量；其早期公开数字用随机路由，小 M 不可直接对比）。
- 指标 = 8 rank 平均耗时（us）的跨 rep median：M≤64 median-of-5，
  M128-1024 median-of-3，M≥1280 median-of-2。小 M（M≤4）run-to-run 噪声
  ±15-30%，逐点对比请以 median 与同日相对座次为准。
- "我们 int4a8 (ZP, v3)" = QServe 两级量化 + zero point（客户格式）
  + 预存解码表（PRELUT）+ 小 M 2-CTA/SM 低延迟档（自动按 M 与模型档位启用：
  pro M1-8 / flash M2-8；其余点与基础路径逐位一致）。
  M≤1024 走 inline swapAB 档（block_n=128），M≥1280 走 PRE 预解码档
  （block_n=256，decode + GEMM 全计入）。
- 对比列：FP8 = AichenF fork 的 SM90 FP8 MegaMoE；FP4 = deepseek-ai/DeepGEMM
  PR#323 的 SM90 FP4 MegaMoE（3c1d617 基版）。

## 读表要点

- **小 M（decode 延迟敏感区）：flash M1/M2 与 pro M1 全行最快是我们**——
  int4 权重带宽减半 + 预存表解码（每 16 权重零乘法）+ 2-CTA/SM 低延迟档
  （机制：小 M 下 GEMM 流水线延迟受限而非带宽受限，两个常驻 CTA 提供两条
  独立流水线互相吸收 mbarrier 唤醒与尾部收敛的气泡）。pro M2-M8 与 FP4
  差距 3-12%。
- **中 M（M16-256）**：整数格式的解码符号运算与 I2F promote 是相对 FP4 的
  固有格式税（issue-bound 区间），约 +5-30%；M≥128 起 FP8 开始领跑。
- **大 M（M≥1280，PRE 档）**：预解码把逐 tile 重复解码变为 O(1)，
  对 FP8 收敛到 +8-13%（8-bit 权重读放大是主要残差），权重显存为 FP8 的一半。
- **zero point 的代价**：解码查表指令数与对称格式完全相同（zp 与 s2 的乘积
  预存进解码表）；若客户模型可用对称 int4 量化，小 M 还有少量余量。
