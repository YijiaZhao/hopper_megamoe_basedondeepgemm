# W4A8-int MegaMoE 18 点性能表（2026-07）

## 测量口径

- 8×H20-3e，NVLink 全互联，SM 锁频 1830 MHz，测量期间无其他负载。
- balanced routing（`DG_BALANCED_ROUTING=1`），复现命令见 README §六。
- 指标 = 8 rank 平均耗时（us）的跨 rep median：M≤64 median-of-5，
  M128-1024 median-of-3，M≥1280 median-of-2。小 M（M≤4）run-to-run 噪声
  ±15-30%，逐点对比请以 median 为准。
- "我们 int4a8 (ZP)" = QServe 两级量化 + zero point（客户格式），
  M≤1024 走 inline swapAB 档（block_n=128），M≥1280 走 PRE 预解码档
  （block_n=256，decode + GEMM 全计入）。
- v3（2026-07-13 同日整表复测）：在 ZP+PRELUT 基础上叠加小 M 2-CTA/SM
  低延迟档（`DG_W4A8_INT_SMALLM_OCC2=1`，自动按 M 与模型档位启用：
  pro M1-8 / flash M2-8；其余点与原路径逐位一致）。
- 对比列：FP8 = AichenF fork 的 SM90 FP8 MegaMoE（同日同机复测）；
  FP4 = deepseek-ai/DeepGEMM PR#323 的 SM90 FP4 MegaMoE（早期同机测量值，
  同口径；其 HEAD 后续调优 commit 未包含）。

## 读表要点

- **小 M（decode 延迟敏感区）**：int4 权重带宽减半 + 寄存器 LUT 解码见效；
  v3 的 2-CTA/SM 低延迟档（机制一句话：小 M 下 GEMM 流水线是延迟受限而非
  带宽受限，两个常驻 CTA 提供两条独立流水线互相吸收 mbarrier 唤醒与尾部
  收敛的气泡）把 pro M8 与 FP4 的差距从 ~17% 收敛到 ~3%、flash M8 到 ~5%；
  pro M1-M4 与 FP4 差距 ~3-8%。flash M1 未启用该档（该点协议开销主导，
  双 CTA 反而变慢），与 FP4 差距在小 M ±15-30% 噪声带内。
- **中 M（M16-128）**：整数格式的解码符号运算与 I2F promote 是相对 FP4 的
  固有格式税（issue-bound 区间），约 +5-30%。
- **大 M（M≥1280，PRE 档）**：预解码把逐 tile 重复解码变为 O(1)，
  对 FP8 收敛到 +8-13%（8-bit 权重读放大是主要残差）。
- **zero point 的代价**：解码查表指令数与对称格式完全相同（zp 折叠进 LUT 表项）；
  残余成本只在每行×每 K128 段的建表处，flash 上在噪声带内，pro（K 段更多）
  中小 M 约 +5-7%。若客户模型可用对称 int4 量化，pro 小 M 还能再快 ~5-10%。
